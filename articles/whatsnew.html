What's new

Changes in each release of the Yak2D package that affect applications. yak2D follows semantic versioning from 1.1.0: 1.x.y releases never break your code, so you can always update within 1.x with:

dotnet add package Yak2D

The full history is in the yak2d repository.

1.3.0 (November 2026)

  • Behaviour change on OpenGL: textures made from pixel data are now the same way up on every graphics API. CreateRgbaFromData() and CreateFloat32FromData() now treat index 0 as the top-left pixel and row 0 as the top of the image on OpenGL too, as they already did on Vulkan, Direct3D11 and Metal, so one array draws the same way up everywhere. If your application flipped pixel rows itself for OpenGL, remove that flip, or the texture now draws upside down on OpenGL. LoadTextureColourData() also returns row 0 at the top on every graphics API now, so its output can go straight into CreateRgbaFromData(). See Textures from data.
  • New YAK2D_TEXTURE_ROWS_BOTTOM_UP define in custom shaders compiled with useSpirvCompile: true, for texture coordinates a shader computes itself (FTex is already correct everywhere). Shaders that don't use it work as before. See Custom shaders.
  • Draw layers 10 and above now draw. Before, anything drawn on layer 10 or higher was lost. See Layers and depth.
  • Fixed the second texture (Texture1) of a DualTextured draw request being sampled upside down on Vulkan; it now matches the other graphics APIs.
  • Ubuntu: the bundled SDL2, shaderc and spirv-cross libraries now load without installing any system packages.

1.2.3 (November 2026)

  • Custom shaders on OpenGL: with SPIR-V compiled shaders, textures are now bound by name, so a shader that reads more than one texture gets the right one on OpenGL. Name each texture Texture_<Name> and its sampler Sampler_<Name>, after the uniform description's Name. See Custom shaders.

1.2.2 and 1.2.1 (November 2026)

  • Window resizing: fixed crashes and errors that could happen while the window was being resized, when the window's render target was recreated at the same moment a frame was being presented.

1.2.0 (October 2026)

  • Correct transparency on render targets. BlendState.Alpha now keeps a surface's alpha channel correct. Before, translucent shapes drawn onto a render target lowered its alpha, so they came out too dark after effects such as colour effects and distortion. Drawing onto opaque surfaces looks exactly as before.
  • New BlendState.Premultiplied for drawing a transparent render target over something else without dark edges. See Transparent render targets, and the Cookbook recipe.
  • Lighter image loading: images are now decoded with StbImageSharp instead of ImageSharp. The same formats are supported (PNG, JPG, BMP, GIF and TGA) and nothing changes in your code.
  • Fixed a crash when a stage was destroyed in the same frame as shutdown or a device reset.

1.1.0 (September 2026)

The first stable 1.x release.

  • Faster, stable draw sorting: draw requests are sorted about twice as fast, and the sort is now stable: requests that would otherwise sort equally (same layer, depth and textures) always draw in the order they were submitted, instead of possibly swapping between frames.
  • Licence: the package is now MIT licensed throughout (the last Apache-licensed code was removed).
  • Built on NeoVeldrid 1.2.1 and .NET 10, with SDL2 and all native libraries included in the package.
Note

Version 1.0.0 is deprecated and unlisted on NuGet. Use 1.1.0 or later.
